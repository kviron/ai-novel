# Глобальная оболочка приложения и переносимый контекст проекта

Дата: 2026-09-24  
Статус: дизайн согласован в чате; ожидает просмотра документа пользователем.

## Цель и границы

Создать единую навигационную оболочку для библиотеки, каталога персонажей, студии и игрового экрана. Первый экран остаётся библиотекой новелл с компактной компоновкой, вдохновлённой боковой навигацией `dashboard-01`, но без аналитических карточек, таблиц и графиков. Подготовить репозиторий так, чтобы после клонирования на другом ПК были понятны архитектура, текущие возможности и порядок запуска.

Работа не включает редактор персонажей, сюжетный граф, активную генерацию изображений, изменение модели через интерфейс или перенос пользовательской SQLite через Git. Дорожная карта сохраняет эти функции как будущие этапы.

## Архитектура интерфейса

В `app` появляется один route layout: провайдер сайдбара, глобальное меню и область содержимого с `Outlet`. Все существующие маршруты (`/`, `/play/:sessionId`, `/studio`, `/studio/:sessionId`) становятся его дочерними маршрутами. Новые разделы: `/characters` и `/settings`. Смена раздела выполняется клиентским роутером без перезагрузки страницы. Текущий глобальный раздел виден в навигации; вложенные игровые и студийные маршруты подсвечивают соответственно «Библиотеку» и «Студию».

В меню только общие разделы: «Библиотека», «Персонажи», «Студия», «Настройки». Название новеллы, сцена, состояние сессии и действия автора остаются внутри соответствующей страницы и никогда не добавляются в глобальное меню. Локальная тема новеллы применяется только к области игры/студии; системная навигация остаётся на системных токенах shadcn. Это сохраняет возможность в будущем менять палитру и оформление каждой истории без влияния на глобальную оболочку.

Используются компоненты shadcn из текущего пресета `b1D1mJdI` (Mira) — прежде всего `Sidebar` и его штатные элементы. `dashboard-01` служит ориентиром компоновки, но не устанавливается как целый блок. Приложение собирает из библиотечных компонентов собственное меню, не создавая новый низкоуровневый UI-примитив. На настольном экране при входе в игру меню стартует свёрнутым; на остальных страницах — развёрнутым. Пользователь может свернуть или раскрыть его в любом разделе. В свёрнутом состоянии меню по умолчанию скрывается целиком, включая иконки. Небольшая отдельная кнопка открытия остаётся доступной на экране игры и других страницах, чтобы навигацию всегда можно было вернуть. На узком экране меню открывается поверх содержимого штатным мобильным режимом Sidebar. Переключатель доступен с клавиатуры, имеет понятное доступное имя и не перекрывает управление сценой в закрытом состоянии.

Настройка «Показывать иконки при сворачивании» меняет режим сворачивания глобально: выключена — меню полностью скрыто, включена — остаётся полоса иконок. По умолчанию выключена, в том числе для игры. Изменение применяется сразу на всех страницах и сохраняется в `localStorage` этого браузера; серверной синхронизации и переноса между ПК пока нет. Если доступ к `localStorage` запрещён, приложение продолжает работать с настройкой по умолчанию без ошибки страницы.

При переходе между разделами текущая игровая сессия не удаляется: её URL продолжает восстанавливать прохождение. Глобальное меню не обещает автоматического возвращения к последней сессии, потому что такого хранилища в текущем контракте нет. Явные локальные ссылки между игрой и тестовой студией продолжают вести в ту же сессию.

## Разделы и данные

**Библиотека** (`/`) — первый экран с заголовком, кратким вводным текстом и существующими карточками историй. Кнопка запуска создаёт сессию через действующий API. Экран компактнее текущего: умеренная типографика и расстояния, без фиктивных метрик и виджетов из примера `dashboard-01`.

**Персонажи** (`/characters`) — общий каталог персонажей всех доступных историй, а не список текущей новеллы. Клиент получает `GET /api/stories`, затем `GET /api/stories/{id}` для каждой истории, и показывает персонажа вместе с названием истории. Данные только для чтения: сервер пока не предоставляет CRUD каталога. Никакой кнопки «создать/редактировать» без работающего действия. Ошибка одной истории не скрывает успешно загруженных персонажей; пользователь видит предупреждение о неполных данных и может повторить загрузку. Пустое состояние отдельно объясняет отсутствие персонажей.

**Студия** (`/studio` и `/studio/:sessionId`) сохраняет текущий работающий запуск тестовой сессии и инспектор. Глобальное меню не заменяет локальные инструменты автора.

**Настройки** (`/settings`) на этом этапе содержат работающую локальную настройку показа иконок при сворачивании, а также фактическое состояние провайдера и доступных моделей из `GET /api/providers` с понятными состояниями загрузки/ошибки и повторной проверкой. Изменение провайдера или модели не изображается работающим, пока для него нет серверного контракта. Системное меню как раздел готово к последующему расширению.

## Переносимость через Git

В корне репозитория появится короткий `AGENTS.md`: назначение проекта, карта каталогов, инварианты игрового состояния, границы реализованного и будущего, команды проверки и ссылки на дорожную карту. Это версия проектного контекста, которую можно получить после клонирования на другом ПК. `README.md` будет обновлён: нейтральные команды `git clone`, вход в каталог без жёсткого пути разработчика, установка зависимостей, `.env`, локальная модель Ollama, запуск API и web, проверка. В дорожной карте будет отражена новая общая оболочка как промежуточная инфраструктурная работа без преждевременного объявления этапа 2 готовым.

В Git входят код, документы и пример переменных окружения. Локальные `.env`, веса Ollama и SQLite с пользовательскими прохождениями не входят; README явно предупреждает об этом. Для переноса пользовательских данных потребуется отдельный backup/export в будущем.

## Проверка готовности

- На всех маршрутах доступна одна глобальная оболочка с сайдбаром; из игры можно перейти к персонажам, библиотеке, студии и настройкам.
- При входе в игру на настольном экране сайдбар полностью скрыт по умолчанию, но возвращается кнопкой. Настройка включает полосу иконок в свёрнутом состоянии, действует во всех разделах и сохраняется после перезагрузки браузера.
- Игровая сцена сохраняет свою тему; системное меню не наследует цвета новеллы. Существующая сессия восстанавливается по прежнему URL после навигации.
- В каталоге персонажей корректны загрузка, пустое состояние, частичная и полная ошибка; каждый персонаж имеет привязку к истории.
- Настройки показывают реальные данные провайдера, а не неработающие контролы.
- Клавиатурное управление и мобильное открытие/закрытие навигации проверены в браузере.
- Проходят frontend unit/component tests, `npm run check` и относящиеся к навигации E2E. README проверен на отсутствие машинно-специфического пути и непредусмотренных секретов.
