# Переносимые изображения Эшли

## Цель

Создать для уже существующей в каталоге Эшли аватар и три согласованных полноразмерных спрайта (`neutral`, `happy`, `angry`), показывать их в каталоге и игровой сцене и включать в ZIP-экспорт персонажа. Изображения принадлежат ревизии персонажа, а не конкретной новелле или локальному UUID.

## Исходный образ

Источник истины — сохранённая ревизия Эшли: взрослая 30-летняя высокая стройная эльфийка с белыми волосами, заострёнными ушами, небольшой татуировкой бабочки на ладони, изысканным вкусом в одежде. Она мягкая в общении, но требовательная, опытная лучница и следопыт. Генерируем аниме-иллюстрации, совместимые по стилю с существующими спрайтами. Для визуальной связности выбираем один элегантный тёмно-изумрудный наряд с серебряными деталями; это художественное решение для материалов, не изменение текстового канона. Эмоции меняют только выражение лица и небольшие детали позы, не идентичность, одежду или пропорции.

## Выбор архитектуры

Вариант с `if (character.name === 'Эшли')` и импортом PNG из веб-пакета прост, но ломает перенос персонажа и зависит от имени либо локального ID. Выбран существующий механизм версионируемых `character_materials`: новые виды `sprite_neutral`, `sprite_happy`, `sprite_angry` рядом с `avatar`. Чтение изображения остаётся через существующий `/api/character-materials/{id}`. `CharacterSprite` получает URL через данные сессии и не знает, откуда взят файл.

## Контракт и поток данных

- API принимает PNG для трёх фиксированных видов спрайта через действующий маршрут загрузки материала; проверяет размер, сигнатуру, происхождение и ревизию так же, как для аватара. Каждый вызов создаёт новую ревизию и переносит остальные материалы из прежней ревизии. Для этой поставки последовательные четыре загрузки допустимы.
- Текущая ревизия профиля и закреплённая ревизия персонажа в сессии возвращают `sprites: { neutral?: MaterialProfile, happy?: MaterialProfile, angry?: MaterialProfile }`. Снимок сессии не меняется при последующем обновлении каталога.
- Клиент выбирает выражение активного персонажа по `visual_directive.emotion`, а для молчащего — `neutral`; при отсутствии нужного выражения берёт `neutral`, затем существующий плейсхолдер. Аканэ и Марк сохраняют свои текущие специальные ресурсы до отдельной миграции.
- ZIP формата 2 добавляет эти три материала в каждую ревизию. Импорт принимает форматы 1 и 2, проверяет список допустимых видов, хэши, MIME, размеры и отсутствие лишних файлов. Экспорт старых персонажей без спрайтов остаётся рабочим. Ограничение числа записей архива учитывает максимум материалов на ревизию; общий лимит 50 МБ сохраняется.
- Аватар Эшли загружается в её текущую ревизию с явно указанным AI-assisted происхождением. Спрайты загружаются следом. Готовые PNG также кладутся в репозиторий как исходные проектные материалы для воспроизводимости, но UI не зависит от путей этих файлов.

## Проверки

- Генерация: все четыре изображения узнаваемо изображают одну взрослую Эшли; три спрайта в полный рост с настоящим прозрачным фоном; аватар крупным планом. Отсутствуют надписи и посторонние персонажи.
- API: загрузка трёх видов, наследование материалов между ревизиями, отказ для неизвестного вида, ZIP round-trip и импорт старого формата.
- UI: аватар виден в каталоге и карточке, нужный спрайт — в сцене, нейтральный спрайт остаётся у молчащей Эшли, отсутствие материалов не ломает сцену.
- Общие тесты API и веба, Ruff, TypeScript, сборка и FSD-линтер.

## Не входит

Генерация изображений по кнопке для произвольного персонажа, редактор эмоций, новые эмоции движка, автоматическое обновление уже запущенных сессий и изменение биографии Эшли.
