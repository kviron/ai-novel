# AI Visual Novel v0.1 Design

## Goal

Build a local, single-user visual-novel engine. React renders the story, FastAPI owns objective state in SQLite, Ollama produces structured narrative proposals, and ComfyUI runs only as a headless image backend.

## Architecture

The web client talks only to FastAPI. The API stores stories, adult characters, scenes, turns, generation jobs, and assets. Provider adapters expose Ollama and ComfyUI health independently so the demo remains usable when either service is offline.

The first vertical slice supports story creation, a playable demo turn, job progress, and two image modes: cached character sprites and full-scene CG. A visual profile and reference assets form the stable identity boundary; future LoRA or reference-conditioning implementations fit behind the image adapter.

## State and narrative

SQLite is authoritative. LLM output is treated as a proposal and cannot directly mutate canon. Each turn includes a request ID and expected state version. The server validates and atomically applies accepted changes; duplicate request IDs return the original turn.

## Image pipeline

Creating a story enqueues one character-sheet job per character and dependent sprite jobs for neutral, happy, sad, angry, and surprised expressions. CG jobs use the same visual profile but produce a complete scene. Jobs use `queued`, `running`, `succeeded`, `failed`, and `cancelled` states and expose stage and optional progress. v0.1 includes a deterministic demo worker; the ComfyUI adapter boundary and configuration are ready for live workflows.

## UI

The UI has a story setup screen and a visual-novel stage with artwork placeholder, speaker, narration, dialogue, choices, free-text action, provider status, and generation queue. ComfyUI itself is never embedded.

## Safety and scope

Characters must be at least 18. Mature themes are metadata only. No graphic sexual material is generated by the scaffold. The app binds locally and has no multi-user authentication or public deployment in v0.1.

## Verification

Backend tests cover story creation, age validation, turn versioning/idempotency, and job dependencies. Frontend tests cover creation and play-state rendering. The final gate runs backend tests, frontend tests, production build, and an API smoke check.
