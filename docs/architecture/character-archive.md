# Перенос персонажей и материалов

Персонаж имеет стабильный ID, а каждое изменение профиля, аватара или обложки создаёт новую неизменяемую ревизию. Новелла и уже начатая сессия закрепляют ID конкретной ревизии. Извлечение персонажа из прохождения создаёт новый независимый ID из закреплённой в сессии версии и сохраняет `origin_character_id`; роль и цвет конкретной новеллы не копируются.

## Материалы

`POST /api/characters/{id}/avatar` и `/cover` принимают тело PNG, JPEG или WebP до 10 МиБ. Обязательные параметры запроса: `filename`, `creator`, `license`, `source`. Сервер проверяет сигнатуру, считает SHA-256 и сохраняет файл в `ASSET_DIR` под хешем, а метаданные — в SQLite на ревизии. `GET /api/character-materials/{id}` отдаёт байты только по зарегистрированному ID. Встроенные портреты зарегистрированы с указанием происхождения; их право на повторное распространение помечено как неустановленное.

## Архив

`GET /api/characters/{id}/export` возвращает ZIP с `manifest.json` формата 1 и материалами `assets/<sha256>.<ext>`. Манифест содержит все текстовые ревизии, номера, текущую ревизию, корневой ID происхождения и для каждого аватара/обложки автора, лицензию, источник, MIME, имя и хеш. Секреты провайдеров и игровые сессии не входят. Экспорт и импорт MVP ограничены 100 ревизиями и 50 МиБ архива; если профиль превысил этот предел, экспорт возвращает `archive_limit`, не повреждая профиль. `POST /api/characters/import` проверяет имена всех записей, размеры, поддерживаемый формат, сигнатуры и хеши до создания персонажа. Повторный импорт создаёт ещё одну независимую копию с тем же происхождением.

На странице каталога есть импорт ZIP, на странице персонажа — экспорт и загрузка материалов. На другом компьютере архив импортируется через каталог. Для переноса *игровых сохранений* отдельно копируют SQLite из `DATABASE_PATH`; для загруженных изображений без архивов потребуется также `ASSET_DIR`. Эти локальные данные не попадают в Git.
