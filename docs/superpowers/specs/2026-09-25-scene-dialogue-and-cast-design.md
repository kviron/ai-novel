# Сцена с несколькими репликами и состав новеллы

## Цель

Один ход новеллы должен показывать чередование повествования и реплик нескольких персонажей без повторения речи в описании. Автор управляет цветом персонажа внутри конкретной новеллы через компактный экран состава. Уже сохранённые ходы и начатые сессии остаются читаемыми и не меняются при редактировании состава.

## Выбор формата

Рассмотрены два подхода. Извлечение реплик из одной строки повествования требовало бы ненадёжного разбора кавычек и имён после генерации. Вместо этого провайдер возвращает упорядоченный массив типизированных фрагментов: `narration` с текстом или `dialogue` с `character_id` и текстом. Это сохраняет авторский порядок «действие → речь → действие → речь» и даёт движку проверяемые ID говорящих.

Контракт ответа модели ограничивает число и длину фрагментов. В ходе должна быть хотя бы одна реплика известного персонажа; описания могут находиться до, между и после реплик. Модель не помещает прямую речь в описательный фрагмент. Канонизатор проверяет существующие правила сцены и отклоняет очевидный длинный дословный повтор между описанием и репликой. При ошибке используется уже существующая одна попытка исправления ответа модели; неуверенные совпадения не удаляются автоматически. Версия промпта меняется.

Сохранённый ход получает упорядоченные `segments` как каноническое представление, а публичные ответы API передают их вместе с метаданными хода. Старые строки `narration`, `dialogue` и `speaker` остаются доступными для чтения прежних записей: при отсутствии `segments` сервер строит совместимый набор из старого описания и реплики. Миграция не переписывает художественный текст и не меняет старые ветки. Для новых ходов структурированные фрагменты являются источником отображения и контекста модели; совместимые старые поля заполняются объединённым описанием и последней репликой/говорящим для прежних читателей.

## Цвет и имя персонажа

Цвет — поле связи персонажа с новеллой, а не глобального профиля. Автор выбирает его через color picker; API принимает нормализованный цвет `#RRGGBB` и отклоняет неверные значения. В момент старта сессии цвет копируется вместе с ревизией и ролью в снимок состава. Поэтому изменение цвета в редакторе влияет только на новые сессии. Для старых связей и сессий миграция задаёт безопасный цвет по умолчанию.

Полное имя персонажа не редактируется на экране состава. Короткую подпись интерфейс выводит из первого слова имени из закреплённой ревизии: «Аканэ Куроха» → «Аканэ», «Эшли» → «Эшли». Модель возвращает `character_id`, а не текст имени; короткое имя и цвет определяет приложение из снимка сессии. Это исключает путаницу при нескольких говорящих.

## Отображение сцены и истории

Игровая сцена показывает фрагменты в сохранённом порядке. Описание выглядит как повествование, речь — как отдельный фрагмент с коротким окрашенным именем. Когда говорит один персонаж, его цвет может тонировать верхнюю плашку имени; когда говорят несколько, имя и его цвет показываются у каждой реплики. Текст реплик не дублируется в описании. В модальном окне истории игрок по-прежнему видит своё действие справа, а ответ новеллы слева, но внутри ответа сохраняется тот же порядок фрагментов и подписи говорящих.

## Экран состава

Страница становится шире. Основное содержимое — таблица состава с аватаром, именем, ролью, ревизией и рамкой строки в выбранном цвете. На узком экране та же информация складывается в компактные строки без горизонтального скролла всей страницы. Действия редактирования и удаления появляются при наведении, а также доступны при фокусе и на сенсорном экране.

Кнопка «Добавить персонажа» открывает модальное окно каталога. При открытии клиент запрашивает `GET /api/characters?exclude_story_id=<id>`; сервер возвращает только ещё не добавленных в эту новеллу персонажей. Можно выбрать несколько строк, затем одной кнопкой добавить их. Один пакетный запрос добавляет выбранных персонажей атомарно: при ошибке не добавляется никто, список остаётся открытым с сообщением. После успеха состав и доступный каталог обновляются. У новых участников используются текущая ревизия и цвет по умолчанию; роль уточняется в редакторе участника.

Редактирование открывает широкое модальное окно с выбранной ревизией, ролью, генерацией роли и color picker. Сохранение меняет только связь персонажа с новеллой. Удаление убирает только эту связь и подтверждается отдельно; глобальный профиль и снимки уже начатых сессий остаются. Последнего участника удалить нельзя, чтобы новые сессии не остались без персонажей.

## Границы и проверка

Провайдер отвечает только за предложение фрагментов. Движок валидирует порядок, ID, допустимость визуального состояния и отсутствие явного повтора, затем атомарно сохраняет канонический ход. Репозиторий отвечает за совместимость старых записей и снимки состава. UI только отображает полученные фрагменты и цвета; он не разбирает кавычки и не определяет говорящего из текста.

Тесты покрывают чередование двух говорящих, повтор реплики в описании и повторную генерацию, старую сессию без `segments`, цвет и роль в снимке сессии, фильтр каталога, пакетное добавление, редактирование и удаление связи, а также клавиатурную и мобильную доступность действий таблицы.
