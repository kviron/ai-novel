# Библиотека новелл и игровые сохранения

## Цель

Превратить стартовую библиотеку из списка запуска в каталог новелл и место возврата к игре. Сохранения остаются в SQLite и доступны после перезапуска браузера и API. Текущая версия локальная и однопользовательская; авторизация и синхронизация между компьютерами не входят в эту задачу.

## Интерфейс

Библиотека имеет две вкладки: «Все новеллы» и «Начатые». Первая выбрана при открытии страницы. «Все новеллы» показывает адаптивные карточки с обложкой, названием, расширенной аннотацией и действием «Начать новую игру». Обложка «Эха неона» — отдельный статический файл, оформленный в стилистике истории. Для новелл без обложки предусмотрен аккуратный тематический плейсхолдер, а ошибка загрузки изображения не ломает карточку.

«Начатые» показывает игровые сессии из базы, по одной карточке на прохождение, новейшие сверху. Карточка сообщает название новеллы, текущую сцену, время последнего изменения и ведёт действием «Продолжить» к существующему `/play/:sessionId` без создания новой сессии. Несколько прохождений одной новеллы остаются доступными по отдельности. Пустое состояние прямо предлагает перейти к «Все новеллы». Загрузка и ошибки списка сохранений не мешают просматривать каталог; доступен повтор запроса.

На узком экране карточки переходят в одну колонку. Размеры текста, отступы, вкладки, кнопки и состояния используют существующий preset shadcn `b1D1mJdI` и тему приложения. Пользовательские цвета новеллы не окрашивают глобальную навигацию.

## Данные и API

В `Story` добавляются `description` (развёрнутая аннотация) и `cover_image_url` (необязательный путь обложки). Оба поля входят в `StorySummary`, используемый библиотекой; краткий `premise` остаётся для сцены и существующих клиентов. Alembic-миграция добавляет поля к существующим SQLite и заполняет аннотацию и обложку встроенной новеллы, не пересоздавая её и не трогая прохождения. Обложка поставляется вместе с веб-приложением по стабильному URL.

В `StorySession` добавляется `kind`: `player` или `author`. Для существующих строк значение по умолчанию — `player`, чтобы старые прохождения сохранились в «Начатых». Создание сессии из библиотеки явно задаёт `player`, из студии — `author`. Метка неизменна после создания и служит для организации интерфейса, а не для защиты доступа. Значение `updated_at` обновляется при подтверждённом ходе и используется для сортировки.

Новый `GET /api/sessions?kind=player` выдаёт лёгкие сводки: ID сессии, сводку новеллы, текущую сцену, версию состояния, дату создания и последнего изменения. Он не возвращает полную историю ходов и сырые ответы модели. Запрос фильтруется в SQL, сортируется по `updated_at DESC, id DESC`. API создания сессии получает явный режим от соответствующего пользовательского потока; при прямом вызове без режима сохраняется совместимый default `player`.

Пока в приложении нет учётных записей, список относится ко всей локальной базе на этом ПК. Будущая многопользовательская версия потребует отдельного разграничения доступа; нынешний endpoint не следует выставлять в публичный интернет как персональные сохранения.

## Границы кода

Бэкенд: миграция, модель, репозиторий/сервис/схемы и маршруты модуля `stories`. Фронтенд: типы и вызов списка в `shared/api`; состояние вкладок, получение списков и карточки — внутри `pages/novel-library`. Студия передаёт `author` при создании теста. Не вводим новую сущность или общий слой карточек без второго потребителя. Статическая обложка с фиксированным URL живёт в `apps/web/public/covers/`.

## Проверка

Бэкенд-тесты подтверждают миграцию старой базы, сохранность старых ID, фильтрацию игровых/авторских сессий, порядок по последнему ходу и отсутствие лишних полей. Фронтенд-тесты проверяют обложку и аннотацию, вкладки, пустое/ошибочное состояние, продолжение без `POST` создания и маркировку тестовой сессии студии. Браузерный сценарий создаёт игровую сессию, возвращается в библиотеку и продолжает именно её после перезагрузки. Финальная проверка: lint, типы, тесты, сборка и визуальный осмотр десктопа и мобильной ширины.
