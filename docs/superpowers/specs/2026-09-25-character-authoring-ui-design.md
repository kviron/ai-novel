# Авторский интерфейс персонажей

Глобальный каталог владеет профилем персонажа и его неизменяемыми ревизиями. Экран состава новеллы владеет только связью новеллы с одной выбранной ревизией. Тестовая студия остаётся инспектором сессии и лишь даёт ссылку на экран состава.

Автор создаёт персонажа в каталоге через короткую форму. Страница профиля создаёт новую ревизию, не редактируя старую. Экран состава показывает всех персонажей каталога, отмечает уже добавленных, позволяет выбрать ревизию и либо добавить персонажа, либо переключить закреплённую ревизию. Изменения применяются к новым сессиям; существующие прохождения сохраняют свой snapshot.

Редактор занимает отдельный маршрут `/characters/new` или `/characters/:id/edit`. Он делит сведения на основу, характер и роль, внешность, биографию и визуальные материалы. Визуальный блок пока показывает существующий портрет или пустое место для будущих аватара и спрайтов. Поля используют существующие UI-примитивы приложения и контракт `CharacterWrite`; пол выбирается через shadcn Select.

У каждого текстового описания есть действие генерации. Оно отправляет весь несохранённый черновик на `POST /api/characters/generate-field`, где сервер выбирает работающую модель Ollama и просит расширить только указанное поле, сохранив факты автора. Результат остаётся редактируемым черновиком и не создаёт ревизию до явного сохранения. Если модель опустила исходную фразу, сервер добавляет её дословно. Ошибки генерации и записи показываются на странице с возможностью повторной попытки. Визуальная генерация, загрузка изображений и перенос персонажей в JSON остаются отдельными срезами.
