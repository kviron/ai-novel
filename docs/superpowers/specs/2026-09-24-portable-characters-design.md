# Переносимые персонажи: первый рабочий срез

Дата: 2026-09-24. Статус: проектное решение для первого среза этапа 2.

## Цель и граница

Аканэ и Марк становятся персонажами локального каталога, а не строками, принадлежащими одной истории. Одну подтверждённую ревизию можно использовать в нескольких новеллах. Новая ревизия не меняет канон новеллы или уже начатое прохождение без явного действия автора.

Этот срез включает миграцию SQLite, глобальное чтение каталога, создание персонажа, создание новой ревизии профиля и привязку выбранной ревизии к новелле. Текущий игровой и студийный сценарии продолжают работать. Графический редактор, импорт/экспорт с материалами, загрузка файлов и перенос памяти персонажа — отдельные следующие срезы этапа 2. Статус этапа остаётся `planned`, пока его полные критерии из дорожной карты не выполнены.

## Выбранная модель

Сравнивались два варианта: (1) оставить `characters` как строки конкретных новелл и добавить каталог-копию; (2) мигрировать их в стабильные идентичности и неизменяемые ревизии. Выбран второй: один источник профиля избавляет от рассинхронизации и позволяет закреплять точное содержание в сохранении.

- `characters`: стабильный ID, текущая ревизия для каталога, происхождение (`builtin`, `local` или `legacy` для перенесённых старых профилей), дата создания. Поля профиля здесь не дублируются.
- `character_revisions`: неизменяемый профиль — номер, имя, пол, взрослый возраст, характер, внешность, биография, речь, описание роли и дата. Источник и родительская ревизия сохраняются при дальнейшем форке.
- `story_characters`: одна связь персонажа с новеллой, закреплённый ID ревизии и локальная роль. Новая ревизия каталога сама не обновляет связь.
- `session_characters`: снимок связей на момент старта сессии. Игровой контекст, проверка `character_id` и восстановление сессии читают именно его; миграция создаёт записи для существующих сессий.

Существующие глобальные ID `akane` и `mark` сохраняются. Миграция переносит все строки старой `characters`, включая неизвестные тестовые или пользовательские истории, без удаления сессий и ходов. Возраст меньше 18 запрещён для новых профилей; старые данные миграция не удаляет и не исправляет молча.

Для новых персонажей без визуальных материалов игровой движок принимает только нейтральную позу и костюм `none`, а интерфейс показывает именную заглушку. Перенесённые старые профили сохраняют прежние допустимые визуальные значения, чтобы продолжение существующих сохранений не ломалось.

## Контракты и поток данных

Публичный API каталога возвращает ID персонажа, ID и номер текущей ревизии, профиль и происхождение. `GET /api/characters/{id}` возвращает текущую ревизию и историю ревизий. `POST /api/characters` создаёт локальную идентичность с первой ревизией атомарно. `POST /api/characters/{id}/revisions` добавляет неизменяемую ревизию и передвигает указатель каталога; номер версии задаёт сервер. `POST /api/stories/{story_id}/characters` закрепляет выбранную ревизию за новеллой, не меняя существующие сессии. Запросы используют строгую схему и единую русскую форму ошибок.

`GET /api/stories/{id}` и `GET /api/sessions/{id}` сохраняют нынешний формат `characters` для совместимости UI, но собирают профиль через связи с ревизиями. При старте сессии сервер копирует закреплённые ревизии в `session_characters` в той же транзакции, что и сессию. Создание хода загружает только ревизии этой сессии. Для старых сессий миграция закрепляет профиль, существовавший до обновления.

Первый UI-срез переключает каталог на глобальный API и сохраняет текущие карточки, фильтр и профиль. Существующие портреты Аканэ и Марка остаются локальными материалами приложения; модель ассетов и их перенос — следующий срез. Для новых персонажей без материала показывается заглушка без подстановки чужого портрета.

## Ошибки и проверки

Неизвестные ID дают 404; попытка использовать чужую ревизию, повторить связь или создать несовершеннолетний профиль — 422/409 с безопасным кодом. Запись ревизии и смена указателя каталога атомарны; ошибка не оставляет половину операции. Миграция проверяется на пустой и старой SQLite, включая существующую сессию. Contract tests проверяют, что новый профиль виден в каталоге, две новеллы ссылаются на одну ревизию, правка каталога не меняет их до явной перепривязки, а старая сессия остаётся на прежней версии. Frontend и E2E проверяют каталог и переход к профилю.

## Не входит в этот срез

Загрузка файлов, image generation внутри приложения, лицензии и хеши пользовательских материалов, import/export, визуальный редактор графа, `session_character_state` для памяти и отношений. Эти функции не имитируются пустыми кнопками: их интерфейсы появятся вместе с рабочим серверным контрактом.
