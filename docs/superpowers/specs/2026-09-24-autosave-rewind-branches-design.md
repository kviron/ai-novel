# Одна карточка прохождения и откат последних ходов

## Цель и границы

Игрок видит во вкладке «Начатые» одну карточку на новеллу и продолжает её последнее активное автосохранение. В сцене стрелка «Назад» отменяет последний выбор или введённое действие, возвращая предыдущий игровой контекст; после нового выбора прежний путь остаётся альтернативной веткой. Откат доступен не более чем на 10 последних ходов текущего пути. Более ранние ходы сохраняются в SQLite для памяти истории и будущей карты веток.

В этой итерации нет ручных слотов, синхронизации между устройствами и визуальной карты веток. Модель данных не должна мешать их добавлению. Существующие прохождения не удаляются и не объединяются разрушительной миграцией.

## Выбор архитектуры

Простое удаление отменённого хода облегчило бы текущий UI, но уничтожило бы альтернативный путь и сделало карту веток невозможной. Выбрана неизменяемая запись ходов с указателем активной точки в игровой сессии. Откат двигает указатель, а новый ход ссылается на выбранного родителя. Уровень доступа к истории скрыт внутри story engine; браузер не пересчитывает ветки сам.

## Библиотека и автосохранение

Для каждой новеллы хранится один указатель автосохранения (`story_id` → `session_id`) с уникальностью по истории. `GET /api/autosaves` возвращает не более одной сводки на новеллу; библиотека не знает правила выбора среди сессий и показывает ровно одну карточку на ответ. Счётчик вкладки обозначает число новелл, а не число сессий. «Продолжить» открывает указанную сессию. Ручные сохранения впоследствии будут отдельными именованными ссылками на checkpoint внутри этой карточки, а не ещё одним автосохранением.

Миграция выбирает для каждой новеллы последнюю игровую сессию по `updated_at`, затем `id`, и создаёт для неё указатель. Уже существующие дополнительные сессии остаются в базе и не появляются отдельными карточками. «Начать новую игру» создаёт новую сессию и атомарно переставляет указатель, не удаляя старые. Открытие старого прямого URL не подменяет автосохранение. Пока ручных сохранений нет, прежние сессии доступны только через существующий прямой URL; будущий экран сохранений внутри карточки сможет показать их после явного продуктового решения об архиве и ручных слотах.

## Состояние и ветки

Каждый подтверждённый ход имеет неизменяемый ID и ссылку `parent_turn_id` на предыдущий ход активного пути. Для первого хода родитель отсутствует. `StorySession.active_turn_id` указывает на текущее подтверждённое состояние; отсутствие указателя означает стартовую сцену. `state_version` остаётся монотонной ревизией сессии для optimistic concurrency: она увеличивается и при новом ходе, и при откате, даже когда позиция сюжета смещается назад. Поэтому номер ревизии не используется как глубина ветки.

Новый ход строит контекст только из предков `active_turn_id`, а не из последних записанных в таблицу ходов. При сохранении он получает `parent_turn_id = active_turn_id` и становится новым активным ходом. Старые потомки остаются неизменными. Восстановление сессии берёт реплику, выборы и визуальное состояние из активного хода, а не из глобально последнего по времени.

Для текущего движка состояние сцены не меняется между ходами, но каждый checkpoint фиксирует как минимум `current_scene` после хода и уже существующую визуальную директиву. Откат восстанавливает эти поля из выбранной точки, а не только меняет отображаемый текст. Будущие канонические поля должны включаться в checkpoint той же миграцией, которая их вводит. Исторические линейные ходы миграция связывает по возрастанию их прежнего `state_version`; активным становится прежний последний ход. Для старых ходов `current_scene` берётся из сессии, поскольку отдельные сцены ранее не хранились.

## Откат и ошибки

`POST /api/sessions/{id}/rewind` принимает `expected_state_version` и возвращает обновлённый `SessionDetail`. Операция в одной транзакции проверяет ревизию, находит родителя активного хода, перемещает указатель и увеличивает ревизию. Если активного хода нет или пройден предел 10 откатов от текущей верхушки ветки, сервер возвращает понятную ошибку без изменения базы. При конфликте ревизии клиент перезагружает сессию. Запись нового хода сбрасывает счётчик последовательных откатов и начинает новый путь от выбранной точки.

Стрелка «Назад» стоит в интерфейсе сцены, недоступна на стартовой точке, при генерации и при исчерпании лимита. После отката показываются предыдущая реплика и её варианты; отменённое действие можно выбрать или ввести заново. UI использует серверный признак `can_rewind`, не выводит доступность из длины локальной истории.

## Проверка

- Миграционный тест сохраняет старые сессии и ходы, восстанавливает линейные связи, активную точку и один указатель автосохранения на новеллу.
- API-тесты проверяют откат после хода, новую ветку без удаления старой, контекст модели только из активной линии, лимит 10, стартовую точку и конкурентные запросы.
- Компонентные тесты проверяют одну карточку на новеллу, корректный ID «Продолжить» и состояние стрелки.
- E2E: игрок делает ход, откатывает его, выбирает другое действие, перезагружает страницу и видит новую активную ветку. Старую ветку подтверждает API-тест.
